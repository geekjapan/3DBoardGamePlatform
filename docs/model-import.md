# キャラクターモデルの取り込み

駒として立てるキャラクターは **VRM** で用意する。VRM を正規形式にした理由は
[ADR 0002](adr/0002-vrm-canonical-model-format.md) を参照。

## 置き場所と設定

1. VRM ファイルを `assets/models/` に置く。
2. Godot でプロジェクトを開く(またはコマンドラインで `godot --headless --path . --import`)。
   VRM が `.godot/imported/` にシーンとして取り込まれる。
3. キャラクター定義に `model` を書く。

```json
{
  "id": "tsundere",
  "display_name": "ツンデレ司令",
  "personality": "素直じゃないが仲間思い。",
  "model": "res://assets/models/tsundere.vrm",
  "lines": { "moved": ["..."] }
}
```

`model` を書かない、あるいはファイルが無い場合は仮の見た目(プリミティブ)で
動き続ける。欠品でゲームが止まることはない。

**モデルの実体はリポジトリに入れない。** `assets/models/*` は `.gitignore` 済み。
配布モデルの多くは再配布を禁じており、実際に手元の ZZZ モデルの readme にも
「请勿二次配布」(再配布禁止)とある。ファイルサイズも数十 MB になる。

## サイズと向き

**モデル側でサイズを合わせる必要はない。** 読み込み時に実寸を測り、駒として
妥当な高さ(マス一辺の 1.15 倍)へ自動で拡縮し、足元を盤面に接地させる。
身長 1.2m のモデルでも 1.6m のモデルでもそのまま置ける。

前を向く向きだけは VRM の規約どおり **-Z 方向**にしておくこと。

## アニメーション

キャラクターごとにアニメーションを作る必要はない。待機・移動・取られの動きは
**humanoid の役割**(Spine / Chest / Head / LeftUpperArm / RightUpperArm)から
ボーンを引いて適用するので、1 つの定義がリグの違うモデルで共通に動く。

VRM の humanoid 設定さえ埋まっていれば動く。ボーン名は問わない。実際に、
試験用モデルは `LeftUpperArm` の実体が `Left arm` だった。

モデル自身が `idle` / `move` / `capture` に相当する AnimationPlayer のクリップを
持っている場合は、そちらが優先される。

## PMX から VRM への変換

原神・ゼンゼロなどの配布モデルは PMX 形式が多い。Blender を経由して変換する。

### 必要なもの

- Blender(確認は 5.2 LTS)
- **mmd_tools** 拡張 — PMX の読み込み
- **VRM Add-on for Blender** 拡張 — VRM の書き出し

どちらも Blender の `編集 → プリファレンス → 拡張機能` から `blender_org` の
リポジトリで名前を検索して導入できる。

### 自動変換(MMD 標準のボーン名を持つモデル)

ボーン名が MMD 標準(`上半身` `頭` `腕.L` など)なら、humanoid の割り当てまで
機械化できる。GUI を開かずに済む。

```bash
/Applications/Blender.app/Contents/MacOS/Blender --background \
  --python tools/pmx_to_vrm.py -- <入力.pmx> assets/models/<名前>.vrm 1.6
```

最後の数字は目標の身長(メートル)。必須ボーンを自動で埋められなかった場合は、
壊れた VRM を書き出さずにその場で失敗を報告して止まる。そのときは下の手動手順で
割り当てる。

実績: ZZZ の安比(285 ボーンの PMX)をこのスクリプトで変換し、盤上で動作を確認済み。

### 手動の手順

1. **読み込む** — `ファイル → インポート → MikuMikuDance Model (.pmx)`。
   PMX と同じ階層にある `tex` / `spa` などのフォルダは移動させないこと。
   テクスチャは相対パスで参照されている。

2. **スケールを確認する** — mmd_tools は 1 単位 = 8cm 前後で読み込むことがある。
   VRM は 1 単位 = 1m。アーマチュアを選び、身長がおよそ 1.5〜1.8 になるよう
   スケールを調整してから `オブジェクト → 適用 → 全トランスフォーム` で確定する。
   ここを飛ばすと VRM 側の humanoid 設定で弾かれる。

3. **VRM を追加する** — `追加 → VRM → VRM Humanoid`。既存のアーマチュアを
   使う場合は VRM パネルから対象を指定する。

4. **humanoid を割り当てる** — VRM パネルの Humanoid で、必須ボーン
   (Hips / Spine / Chest / Neck / Head / 両腕 / 両脚)に PMX 側のボーンを対応づける。
   日本語ボーン名(`上半身` `頭` `左腕` など)のままでよい。**ここが唯一の
   手作業の山場**で、必須ボーンが埋まらないと書き出せない。

5. **書き出す** — `ファイル → エクスポート → VRM`。警告が出ても、必須ボーンが
   埋まっていれば書き出せることが多い。

6. **確認する** — `assets/models/` に置いてキャラクター定義から参照し、
   ゲームを起動して盤上に立つか、待機で体が動くかを見る。

### つまずきやすいところ

| 症状 | 原因 |
|---|---|
| 盤に出ず仮の見た目のまま | パスが違う。`res://` から書く。インポート(`--import`)を通したか確認 |
| 真っ白・真っ黒 | テクスチャの参照切れ。`tex` フォルダごと移動していないか |
| 体が動かない | humanoid の割り当てが未完。Spine / Chest / Head のどれかが空 |
| 極端に大きい/小さい | 自動で高さは合わせるので、通常は起きない。起きた場合はメッシュが原点から離れている |

## ライセンス

配布モデルは規約が個別に異なる。**再配布禁止・改造禁止・商用利用禁止**が
一般的で、成果物は個人利用に限定される(ADR 0002)。同梱の readme を必ず読むこと。
