# USI連携テストのカバレッジ評価

## 計測時点

現行スイートには **23個のテストファイル、239個のテスト関数**がある。そのうち`tests/test_usi_engine.gd`は **9個のUSIアダプター専用テスト**を持つ。リポジトリにはGDScriptの行・分岐カバレッジを計測するツール設定がないため、本書の「カバレッジ」は計測済みの割合ではなく、公開的なプロトコル境界に対する**振る舞いカバレッジ**として評価する。

## 現在の振る舞いカバレッジ

| 振る舞い | 厳格fake USI | 実機Apery | 評価 |
|---|---:|---:|---|
| `usi` / `usiok` / `isready` / `readyok` の準備 | 実行済み | 実行済み | 高い |
| 強さ設定・`byoyomi`・wire順序 | 実行済み | 時間設定を実行 | 高い |
| 初期局面での合法手 | 実行済み | 弱・中・強の3設定を実行 | 高い |
| 通常移動後の局面 | コーデックで実行済み | 実機シナリオを追加 | 高い |
| 成りが可能な局面 | コーデックとfakeで実行済み | 実機シナリオを追加 | 高い |
| 持ち駒を打てる局面 | コーデックとfakeで実行済み | 実機シナリオを追加 | 高い |
| malformed、無効手、投了、`win` | 実行済み | 非対象 | fakeで決定的に網羅 |
| 検索時間切れ・プロセス終了 | 実行済み | 非対象 | 実機回復シナリオが未実装 |
| 複数手の局面更新と次局開始 | 非対象 | 未実装 | #47で追加する |
| 実プロセスの終了確認 | 非対象 | 未実装 | 診断契約の追加が必要 |
| 複数エンジン・OSの互換性 | 非対象 | Linux/Aperyのみ | 将来の互換性マトリクス候補 |
| 行・分岐カバレッジ率 | 未計測 | 未計測 | ツール導入が必要 |

## 優先度付きの強化案

| 優先度 | 提案 | 効果 | 着手条件 |
|---:|---|---|---|
| P0 | #47のS1〜S4を実装する。8手の実機対局、有限探索時間、fake終了後の次局回復、新規初期局面を検証する。 | 局面更新、失敗隔離、プロセス再初期化をカバーする。 | #46の完了 |
| P1 | `USI_SOAK_PLIES`を入力に持つ手動ワークフローを追加し、40手以上の長時間検証をPRゲートから分離する。 | 通常CIの安定性を維持しつつ、エンジン更新時に長期挙動を調査できる。 | #47の通常8手シナリオ |
| P1 | 実機テスト用に、局面名、SFEN、USI position、結果分類、経過時間のJSON成果物を失敗時に保存する。 | CI失敗を再現・分類しやすくする。 | #47 |
| P2 | Linux/Aperyに加え、別実装のUSIエンジンを任意の互換性マトリクスとして導入する。 | 特定エンジン固有の寛容さに依存しない。 | 固定取得・ライセンス・実行時間の合意 |
| P2 | 実プロセスの生存確認を可能にする公開診断契約を定義し、`quit`後に残存プロセスがないことを検証する。 | zombieプロセスや終了漏れを検出する。 | アダプターの公開診断APIの設計 |
| P3 | GDScript向けの行・分岐カバレッジ計測を導入し、USIアダプターのカバレッジ下限をCIで可視化する。 | 現在の振る舞い評価を定量的な回帰指標へ補完する。 | ツール選定とCI時間の評価 |

## 判断

現時点で最も価値が高い次の一手は、#47のS1〜S4である。これは新しいテスト専用インフラを増やさず、既存のUSIアダプター、コーデック、ルールエンジン、CI入口を通るため、実機連携の主要な未検証経路を最小の追加複雑性で埋められる。
